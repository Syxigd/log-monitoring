# 本地安全检查说明

## 目的

本检查用于提交前的本地安全复核，不依赖 GitHub Actions，也不替代专业运维、依赖治理或生产发布审批。本阶段不执行完整 Maven 构建、完整测试、前端构建或部署。

## 1. 敏感信息扫描

在项目根目录执行只读扫描，优先使用本机已安装的 `rg`：

```powershell
rg -n -i --glob '!target/**' --glob '!node_modules/**' --glob '!.git/**' `
  'password\s*[:=]\s*[^\s`"'']+|secret[-_ ]?key\s*[:=]|access[-_ ]?key\s*[:=]|bearer\s+[A-Za-z0-9._-]+|BEGIN (RSA|OPENSSH|EC|PRIVATE) KEY' .
```

检查结果只能报告文件和行号，不能把匹配行原样复制到工单或提交信息。`.env`、`.env.*`、私钥和扫描输出由 `.gitignore` 保护，但源码和配置目录不得作为扫描排除项。发现真实值时，先移除版本库暴露面，再按凭据轮换清单处理旧凭据。

## 2. 依赖漏洞扫描

- Maven：使用组织批准的 OWASP Dependency-Check 或等效工具，记录工具版本、数据库更新时间、模块范围和报告路径。
- pnpm：使用组织批准的 `pnpm audit` 或等效 SCA 工具，记录锁文件、审计范围和修复责任人。

报告应写入系统临时目录或明确被忽略的扫描目录，不得把完整报告提交到 Git。无法联网或数据库过期时，结果标记为“未验证”，不得写成“无漏洞”。

## 3. 输入与高风险操作检查

- SQL：确认 `MysqlTool.query` 经过 `SqlReadOnlyGuard`，并拒绝写操作、多语句、锁定读和文件导出；表名参数必须通过标识符校验。
- Docker：确认 `docker.restart` 在 `AILOG_MCP_DOCKER_RESTART_ENABLED=false` 时被拒绝。
- RustFS：确认 `rustfs.put` 和 `rustfs.delete` 的写操作在默认策略下被拒绝；删除开关默认关闭。
- WebSocket：确认 `dashboard.allowed-origins` 不为空、不为 `*`，生产只配置明确的 HTTPS 来源列表。
- 路径和容器 ID：后续新增工具必须使用白名单/格式校验，禁止把用户输入直接拼接到 shell 或路径。

## 4. 配置检查

检查以下条件：

1. `application.yml` 只包含非敏感默认值和 `${AILOG_*}` 引用。
2. `application-dev.yml`、`application-test.yml`、`application-prod.yml` 不包含真实凭据。
3. 生产必填变量没有危险默认值，缺失时启动失败。
4. `.env.example` 只使用占位值，`.env` 和扫描输出不会被 Git 跟踪。
5. 高风险 MCP 开关默认值为 `false`。

## 5. 失败退出条件与责任

以下任一情况出现，安全检查结论为失败：发现真实凭据或私钥；生产配置包含高风险默认值；高风险操作在默认配置下可执行；WebSocket 允许通配符；扫描工具返回漏洞阻断级别；扫描范围或工具版本无法确认。开发负责人负责修复代码和文档问题，运维负责人负责凭据、部署变量、密钥系统和外部服务验证。
