# 第一阶段：工程基线与安全清理开发大纲

> **For agentic workers:** 本文档是第一阶段实施计划。执行其中任务时，必须逐项核对文件范围、前置条件、验收标准和外部责任边界；每完成一项都要同步更新“已完成 / 未完成 / 待验证”状态。

**目标：** 建立可安全配置、可追踪、可审计的工程基线，清理当前已知的凭据、SQL、MCP 高风险操作和跨域安全问题，为后续公共模型、事件可靠性和业务闭环开发提供稳定起点。

**架构：** 本阶段不改变项目的模块化单体架构，不引入微服务、配置中心或新的持久化中间件。配置采用 Spring Boot 多 profile 组织，公共配置与环境差异分离，敏感值通过 `AILOG_` 前缀环境变量注入；MCP 工具按风险分级，查询能力与高风险写/运维动作分开控制。

**技术栈：** Java 21、Spring Boot 3.4.4、Maven 多模块、Spring AI 1.0.0-M6、Spring JDBC、Spring Data Redis、RocketMQ Client、docker-java、AWS S3 SDK、React 19、TypeScript、Vite、pnpm。

**依据文档：** [总开发大纲](开发大纲.md)、[项目指令](../AGENTS.md)、[总体设计文档](../DESIGN.md)。

## 全局约束

- 本阶段只生成和执行工程基线、安全清理及配置规范任务，不开发 Planner、Executor、Validation、前端业务页面或 LLM 能力。
- 本阶段不创建 GitHub Actions，不建设 CI 流水线。
- 本阶段不执行完整 Maven 构建、完整 Maven 测试、前端 typecheck、lint 或 build；这些属于后续验证阶段。
- 本阶段不引入外部配置中心或密钥管理平台，先使用环境变量和本地 `.env.example` 规范。
- 真实凭据不得继续写入 `application.yml`、profile 文件、示例脚本、日志或文档。
- 所有外部凭据轮换属于外部运维动作，开发人员只负责提供清单、顺序、验证方式和回滚说明。
- 当前仓库的 Java 编译约束必须保留：使用 `maven.compiler.source` / `maven.compiler.target`，不要恢复 `--release 21`。
- MCP 查询类工具默认允许；Docker 重启、RustFS 删除和未来数据库写操作默认关闭。
- 高风险操作只有在认证、授权、审批、审计和回滚条件同时满足时才允许启用。
- 每项任务完成后必须明确记录已完成、未完成、待验证和阻塞项，不得将设计完成表述为代码完成。

## 2. 阶段目标与非目标

### 2.1 目标

完成本阶段后，应达到以下工程状态：

1. 代码库中不再保存真实数据库、缓存、消息队列和对象存储凭据。
2. 开发、测试、生产配置能够明确分离。
3. 所有敏感值都有统一的 `AILOG_` 环境变量名称。
4. MySQL 工具只能执行明确允许的只读查询。
5. Docker 重启和 RustFS 删除默认不可用，启用时必须经过统一安全策略。
6. WebSocket 允许来源不再使用无限制通配符。
7. 开发人员和运维人员知道各自负责的配置、轮换和验证工作。
8. 本地可以重复执行安全检查，不依赖 CI。
9. 文档可以准确区分实现完成、外部动作完成和待验证事项。

### 2.2 非目标

本阶段明确不做：

- 不实现 Planner、Executor、Validation Engine。
- 不实现完整事件持久化、事件重放或 RocketMQ EventBus。
- 不实现多事件关联和 LLM 根因分析。
- 不开发仪表盘、事件中心和根因分析前端页面。
- 不建设 GitHub Actions。
- 不引入 Vault、Nacos、Apollo、Kubernetes Secret 等外部密钥平台。
- 不重构全部 MCP 工具为复杂 DTO 层。
- 不处理与本阶段安全/配置基线无关的业务重构。

### Task 5：实现 MySQL 查询只读约束（P1）

**目标：** 防止 MCP 查询接口被用于执行写操作、多语句或注入型输入。

**文件：**

- 新增：`mcp-tool-center/src/main/java/com/ailog/mcp/security/SqlReadOnlyGuard.java`
- 修改：`mcp-tool-center/src/main/java/com/ailog/mcp/MysqlTool.java`
- 新增：`mcp-tool-center/src/test/java/com/ailog/mcp/security/SqlReadOnlyGuardTest.java`

**接口建议：**

```java
public final class SqlReadOnlyGuard {
    public void validate(String sql);
}
```

**允许规则：**

- 去除首尾空白后允许 `SELECT`。
- 如确实需要 CTE，允许以 `WITH` 开头，但最终语句必须是只读查询。
- 拒绝空字符串。
- 拒绝多条语句和分号。
- 拒绝注释绕过和明显的 DDL/DML 关键字。
- 不允许通过字符串拼接把用户输入嵌入系统查询模板。

**表名校验：**

- `indexes(String table)` 不直接拼接任意用户输入。
- 表名只允许 `[A-Za-z0-9_]+`，并在执行前校验长度。
- 对需要更强安全边界的场景，先读取数据库元数据再与已存在表名比对。

**实施步骤：**

- [ ] 先编写通过和拒绝用例。
- [ ] 验证空 SQL、SELECT、WITH、INSERT、UPDATE、DELETE、DROP、ALTER、分号和注释输入。
- [ ] 在 `MysqlTool.query` 执行 `JdbcTemplate` 前调用 Guard。
- [ ] 为 `indexes` 增加表名白名单校验。
- [ ] 将拒绝原因转换为不泄露数据库细节的错误信息。
- [ ] 确认异常路径不会访问数据库。

**完成标准：**

- 写操作和多语句在进入 JDBC 前被拒绝。
- 允许的只读查询仍能保持原有查询能力。
- 测试能证明拒绝路径没有调用数据库。

**状态：** 已完成代码侧实现；JdbcTemplate 集成验证未执行。

### Task 6：收紧 Dashboard WebSocket 跨域策略（P1）

**目标：** 移除 `setAllowedOrigins("*")`，改为环境配置的来源白名单。

**文件：**

- 修改：`dashboard/src/main/java/com/ailog/dashboard/config/WebSocketConfig.java`
- 修改：`dashboard/src/main/resources/application.yml`
- 修改：`orchestrator/src/main/resources/application.yml`
- 新增：`dashboard/src/test/java/com/ailog/dashboard/config/WebSocketConfigTest.java`

**规则：**

- 允许来源通过 `AILOG_DASHBOARD_ALLOWED_ORIGINS` 注入。
- 开发环境可配置本地前端地址，例如 `http://localhost:5173`。
- 测试环境使用测试地址。
- 生产环境必须是明确的 HTTPS 域名列表。
- 空白来源或通配符不得作为生产默认值。

**实施步骤：**

- [ ] 定义允许来源配置键和变量格式。
- [ ] 将配置绑定为列表或逗号分隔字符串。
- [ ] 使用配置值调用 `setAllowedOrigins`。
- [ ] 添加通配符和空配置的保护策略。
- [ ] 验证允许来源和拒绝来源的行为。

**完成标准：**

- 生产配置不再出现 `*`。
- 未授权来源不能建立 WebSocket 连接。
- 开发环境仍能连接本地前端。

**状态：** 已完成代码侧实现；真实浏览器连接验证未执行。

### Task 7：建立本地安全检查（P2）

**目标：** 在不依赖 CI 的前提下，为开发者提供可重复的安全检查入口。

**文件：**

- 新增：`docs/安全/本地安全检查说明.md`
- 修改：`.gitignore`
- 可选新增：`tools/security/` 下的只读检查脚本；如果脚本会写文件，输出必须写到被忽略的临时目录。

**检查范围：**

1. 敏感信息扫描：密码、Access Key、Secret Key、Token、私钥和连接串。
2. 依赖漏洞扫描：Maven 和 pnpm 依赖的已知漏洞。
3. 输入安全检查：SQL、路径、容器 ID、RustFS Key 和跨域配置。
4. 配置检查：生产 profile 不允许危险默认值。
5. 高风险工具检查：危险动作默认关闭。

**实施步骤：**

- [ ] 定义本地扫描工具要求和版本记录。
- [ ] 定义扫描排除目录，至少排除构建产物和依赖缓存，但不得排除源码配置目录。
- [ ] 定义误报处理方式，不通过把真实凭据加入排除规则解决。
- [ ] 定义扫描失败的退出条件。
- [ ] 将检查输出写入临时目录并避免进入 Git。
- [ ] 在文档中明确本阶段不执行完整构建和测试。

**完成标准：**

- 新开发者可以按文档运行本地安全检查。
- 扫描范围和排除范围清楚。
- 扫描结果不包含敏感值。
- 检查失败时有明确处理责任人。

**状态：** 已完成检查说明；实际依赖扫描未执行。

### Task 4：建立 MCP 操作风险模型（P1）

**目标：** 统一管理 MCP 工具的风险等级、默认开关和危险操作入口。

**文件：**

- 新增：`mcp-tool-center/src/main/java/com/ailog/mcp/security/McpRiskLevel.java`
- 新增：`mcp-tool-center/src/main/java/com/ailog/mcp/security/McpSecurityProperties.java`

- 修改：`mcp-tool-center/src/main/java/com/ailog/mcp/RustfsTool.java`
- 修改：`mcp-tool-center/src/main/java/com/ailog/mcp/MysqlTool.java`
- 修改：`mcp-tool-center/src/main/resources/application.yml`

**风险分级：**

```text
READ_ONLY
  Docker ps/logs/inspect
  MySQL tables/locks/slowSql/受限 query
  Redis keys/ttl/memory/clusterInfo/monitor
  RocketMQ consumers/lag/retry/deadLetter
  RustFS list/get

HIGH_RISK
  Docker restart
  RustFS delete
  RustFS put
  未来所有数据库写操作
```

**策略接口建议：**

```java
public interface McpOperationPolicy {
    boolean isAllowed(String operation, String actor, String requestId);
    void record(McpAuditRecord record);
}
```

**默认策略：**

- 查询型工具默认允许，但仍需输入校验和外部服务权限。
- `DockerTool.restart` 默认关闭，由 `AILOG_MCP_DOCKER_RESTART_ENABLED` 控制。
- `RustfsTool.delete` 默认关闭，由 `AILOG_MCP_RUSTFS_DELETE_ENABLED` 控制。
- `RustfsTool.put` 视为高风险，不能因为是上传就自动视为低风险。
- 高风险操作被拒绝时返回统一错误，不执行底层 SDK 调用。
- 每次高风险操作必须生成审计记录，至少包含 requestId、operation、actor、target、decision、reason、time。

**实施步骤：**

- [ ] 定义风险枚举和工具方法映射。
- [ ] 定义配置属性和默认关闭值。
- [ ] 在高风险工具方法入口调用策略。
- [ ] 被拒绝时在底层 Docker/S3 调用前返回。
- [ ] 对审计记录做敏感字段脱敏。
- [ ] 为审批结果预留 requestId 和 actor 字段；本阶段不实现完整用户认证系统。

**完成标准：**

- 高风险工具默认不可执行。
- 查询工具和高风险工具有不同策略路径。
- 禁止结果有明确原因。
- 审计记录不包含密码、Secret Key 或完整敏感内容。

**状态：** 已完成默认风险策略和入口控制；认证审批与实际 MCP 调用未完成。
