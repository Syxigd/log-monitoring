# 第一阶段凭据轮换清单

> 状态：代码侧变量迁移已完成；真实凭据轮换未执行。
> 重要：本文只记录字段名、变量名和操作步骤，不记录任何凭据值。

## 1. 责任边界

开发人员负责配置键到环境变量的契约、代码引用和验证步骤；具备权限的运维或系统管理员负责生成新凭据、替换部署变量、撤销旧凭据、记录审计结果。没有外部权限和独立验证记录时，不得将本清单标记为“已完成”。

## 3. 单对象执行卡

每个对象均按以下顺序执行，并在外部审计系统中记录时间、操作者、目标环境、验证结果和旧凭据失效时间；禁止记录凭据值。

1. 轮换前确认当前服务健康、连接池使用情况和影响范围。
2. 由凭据责任人生成符合策略的新凭据，并在受控密钥系统中保存。
3. 先在测试环境注入对应 `AILOG_` 变量，验证应用启动和对应工具的最小访问操作。
4. 在生产部署系统更新变量，采用可回滚的发布方式。
5. 验证应用健康检查以及对应工具访问：MySQL 只读查询、Redis 信息读取、RustFS 列表/读取；不执行破坏性操作。
6. 确认稳定后使旧凭据失效，并记录实际失效时间。
7. 若验证失败，恢复到上一份受控变量版本，确认服务恢复，再分析原因；不得把旧凭据值写入工单。

## 4. 验证方法

| 对象 | 安全验证 | 失败信号 |
|---|---|---|
| MySQL | 启动应用并执行已允许的只读工具查询、表列表或慢查询检查 | 数据源认证失败、连接池无法初始化、工具返回认证错误 |
| Redis | 启动应用并执行内存/集群信息读取 | `NOAUTH`、连接失败或健康检查异常 |
| RustFS | 启动应用并执行指定 bucket 的列表/读取 | AccessDenied、签名失败或 endpoint 连接失败 |
| RocketMQ | 未来启用认证后执行消费者/延迟只读检查 | NameServer/认证失败 |
| Docker | 按 daemon 权限策略执行容器列表检查 | socket 权限失败或 daemon 不可达 |
